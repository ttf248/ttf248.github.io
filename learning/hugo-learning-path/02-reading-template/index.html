用模板把章节连成阅读路径

章节树、面包屑和前后导航，让一组页面不再只是同标签的文章。

所属集合

最后更新
2026年08月11日

内容有了顺序，还需要把顺序交给读者。否则三篇文章只是放在同一个目录里，读者仍然要靠猜测决定下一篇。

学习区的页面壳做了三件小事：左侧目录树告诉读者整门课的形状；面包屑标示当前位置；页面底部给出上一章和下一章。它们都来自同一份目录与 weight，不需要在正文里手动维护链接。

这也是为什么课程不应直接套用博客文章页。博客文章页会强调作者、发布日期、相关文章和评论；学习页面更关心“我现在在哪一节”“本节属于什么集合”“读完之后去哪一节”。两种内容都能使用相同的 Markdown、代码高亮和数学公式，但阅读上下文不同。

在这个站点里，章节树会递归读取集合下的 section 与页面：section 显示为“部分”，叶子页面显示为“章节”。前后导航只扁平化叶子章节，所以“第二部分”的导言不会挤进读者的连续阅读路线。

当内容规模还只有三章时，这些设计看起来略显克制；但它避免了以后从三篇扩展到三十篇时，重新整理链接、搬迁 URL 和修改分类页的成本。
