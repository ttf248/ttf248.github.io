지난해에 SDK를 설계했는데, 이 SDK는 일부 이벤트 처리 및 캡슐화를 담당하고, 클래스 인터페이스를 통해 외부로 제공합니다. 서비스 초기화 시에는 호출자가 해당 클래스를 구현하고 객체 포인터를 모듈에 전달합니다. C11을 접해보다 보니 호기심이 고양이의 목숨을 앗아가듯, 이러한 인터페이스들을 lambda 함수 객체 콜백으로 구현하면 어떤 결과가 나올지 궁금했습니다. 순수 추상 함수의 인터페이스 정의 방법과 비교했을 때 더 유연하다고 생각합니다. 의문이 생겼다. 두 가지 다른 문법 중 성능 면에서 어느 것이 더 빠른가? 컴파일 원리를 모르는 사람이 코드를 조금 작성해서 확인해 보았다.

서론

온라인 주소이며, 다양한 컴파일러와 컴파일 옵션을 선택하고 linux 플랫폼에서 코드를 실행하거나 해당 어셈블리 코드를 확인할 수 있습니다

  • 가끔 기술 검증을 하는데, 웹 페이지에서 짧은 코드 조각을 실행하는 것이 편리합니다
  • Godbolt.org는 다양한 색상으로 다른 어셈블리 코드를 구분하여 로컬 디버거보다 훨씬 편리합니다

본문

표준위원회에서 문법 규칙을 제정했으며, 컴파일 단계에서 어떻게 구현할지는 각 컴파일러에 달려 있습니다. 여기서 짚고 넘어가야 할 것은 마이크로소프트의 컴파일러는 꽤 강력하다는 점입니다. 문법적 설탕이 만능은 아니며, 콜백 인터페이스가 많지 않으므로 lambda를 사용하면 더욱 편리하고 빈 콜백 함수 인터페이스를 정의할 필요도 없습니다. 콜백 인터페이스 종류가 다양해질 때는 전통적인 가상 함수가 비즈니스 인터페이스 정의의 통일성을 더 돕습니다.

  • 윈도우 플랫폼에서는 두 제품의 성능이 거의 비슷하며 큰 차이가 없습니다
  • 리눅스 플랫폼에서 가상 함수와 람다 비교 시, 한 번 실행에 1.35ns 더 걸린다

일반적인 비즈니스 시스템 개발에서는 이 정도의 성능 손실은 무시할 수 있으며, lambda를 도입하면 설계 측면에서 더 많은 편의성을 제공합니다. 특히 다중 신호 처리를 설계할 때 두드러지며, 하단에 이벤트 트리거가 있을 때 로그를 저장해야 한다면 로그 객체를 처리하는 함수가 필요합니다. 더 많은 비즈니스 처리 인터페이스가 필요할 때는 하단에서 vector로 lambda 객체를 저장하고, 이벤트 트리거 시 순차적으로 탐색하며 호출합니다. 이는 QT의 신호와 슬롯과 유사하며, 로그, 모니터링, 비즈니스 1, 비즈니스 2는 서로 완전히 분리되어 있습니다.

#include <iostream>
#include <chrono>
#include <memory>
#include <functional>
#include <atomic>
#include <string>

std::atomic_int64_t counter = 0;

// 定义回调接口
class UserInterface
{
public:
    virtual void name() = 0;
    virtual void full_name() = 0;
};

class User : public UserInterface
{
public:
    void name() {}
    void full_name() { counter++; }
};

void to_string(UserInterface* user)
{
    user->name();
    user->full_name();
}

using name_handler = std::function<void()>;
using full_name_handler = std::function<void()>;

class Test
{
    name_handler name_;
    full_name_handler full_name_;

public:
    void set_name_handler(name_handler name)
    {
        name_ = name;
    }

    void set_full_name_handler(full_name_handler full_name)
    {
        full_name_ = full_name;
    }

    void to_string()
    {
        name_();
        full_name_();
    }
};

int main()
{
    User user;

    auto start = std::chrono::high_resolution_clock::now();

    for (int i = 0; i < 1000000; i++)
    {
        to_string(&user);
    }

    auto end = std::chrono::high_resolution_clock::now();
    std::cout << "Counter: " << counter << std::endl;
    std::cout << "Time: " << std::chrono::duration_cast<std::chrono::microseconds>(end - start).count() << "us" << std::endl;

    counter = 0;
    auto name = []() {};
    auto full_name = []() { counter++; };

    Test test;
    test.set_name_handler(name);
    test.set_full_name_handler(full_name);

    start = std::chrono::high_resolution_clock::now();

    for (int i = 0; i < 1000000; i++)
    {
        test.to_string();
    }

    end = std::chrono::high_resolution_clock::now();
    std::cout << "Counter: " << counter << std::endl;
    std::cout << "Time: " << std::chrono::duration_cast<std::chrono::microseconds>(end - start).count() << "us" << std::endl;

    return 0;
}

사후기

자료를 찾다가 비슷한 코드 조각 functionperformance.cpp를 발견했습니다

#include <iostream>
#include <chrono>
#include <memory>
#include <functional>

using namespace std;
using namespace std::chrono;

class Base
{
public:
	Base(){}
	virtual ~Base(){}
	virtual int func(int i) = 0;
};

class Derived : public Base
{
public:
	Derived(int base = 10) : base{base}
	{

	}
	~Derived(){}

	virtual int func(int i)
	{
		return i*base;
	}
private:
	int base;
};

struct Func
{
	int base;
	int operator()(int i)
	{
		return i*base;
	}
	Func(int base) : base {base}
	{

	}
};
const int base = 10;
int calculate(int i)
{
	return base*i;
}

int main()
{
	const int num = 10000;
	Base *p = new Derived{10};
	int total = 0;
	auto start = high_resolution_clock::now();
	for (int i = 0; i < num; ++i)
	{
		total += p->func(i);
	}
	auto end = high_resolution_clock::now();
	std::cout<<"result: "<<total<<"\nvirtual call elapsed: \t"<<duration_cast<nanoseconds>(end-start).count()<<" nanoseconds.\n"<<std::endl;

	total = 0;
	start = high_resolution_clock::now();
	for (int i = 0; i < num; ++i)
	{
		total += calculate(i);
	}
	end = high_resolution_clock::now();
	std::cout<<"result: "<<total<<"\ndirect function call elapsed: \t"<<duration_cast<nanoseconds>(end-start).count()<<" nanoseconds.\n"<<std::endl;

	Func functor{10};
	total = 0;
	start = high_resolution_clock::now();
	for (int i = 0; i < num; ++i)
	{
		total += functor(i);
	}
	end = high_resolution_clock::now();
	std::cout<<"result: "<<total<<"\nfunctor call elapsed: \t"<<duration_cast<nanoseconds>(end-start).count()<<" nanoseconds.\n"<<std::endl;
	int base = 10;
	function<int(int)> lambda = [base](int i)
	{
		return i*base;
	};
	total = 0;
	start = high_resolution_clock::now();
	for (int i = 0; i < num; ++i)
	{
		total += lambda(i);
	}
	end = high_resolution_clock::now();
	std::cout<<"result: "<<total<<"\nlambda call elapsed: \t"<<duration_cast<nanoseconds>(end-start).count()<<" nanoseconds.\n"<<std::endl;
	return 0;
}

여기에는 일반 함수와 람다 함수라는 두 가지 새로운 모드가 추가되었으며, 인터페이스 콜백 방식과 직접 호출 방식을 비교하여 성능 손실이 수치적인 차이를 보입니다. 람다 함수의 성능은 함수에 근접하며 때로는 더 우수합니다. 컴파일 원리에 대한 지식 부족으로 추측해 보면, 접근하는 변수의 주소와 함수가 서로 인접하여 CPU 처리 측면에서 유리한 것으로 생각됩니다.
