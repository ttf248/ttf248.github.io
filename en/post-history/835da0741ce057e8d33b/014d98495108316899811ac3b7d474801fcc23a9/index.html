  • Last year, an SDK was designed to handle encapsulating certain events and provide a class interface externally. During service initialization, the caller implements the corresponding classes and passes the object pointer to the module.
  • Familiarity with C11 piqued my curiosity, leading me to explore what would happen if these interfaces were implemented using lambda function objects instead of pure virtual function definitions. Compared to the traditional interface definition method, it seemed more flexible.
  • The question arose: with two different syntaxes, which one is faster from a performance perspective? Not understanding compiler principles, I decided to try out some code to find out.

Body

The Standards Committee established grammatical rules, and how these are implemented at the compilation level depends on each compiler vendor. It’s worth noting here that Microsoft’s compiler is quite powerful. Syntactic sugar isn’t a panacea; callback interfaces aren’t abundant, using lambda expressions is more convenient and eliminates the need to define empty callback function interfaces. When callback interfaces become numerous, traditional virtual functions are advantageous for unifying business interface definitions.

  • On the windows platform, performance is nearly identical, with little difference.
  • On the linux platform, a comparison of virtual functions versus lambda reveals a 1.35ns overhead in one instance.

In typical business system development, this level of performance degradation can be ignored; introducing lambda brings more convenience to the design. This is particularly noticeable when dealing with multi-signal processing, where underlying event triggers are used, and functions are needed to handle log entries for input objects. When more business processing interfaces are needed, the underlying layer uses vector to store lambda objects. When an event is triggered, it iterates through them sequentially and calls them one by one, similar to Qt’s signals and slots. Logging, monitoring, Business 1, and Business 2 are completely decoupled from each other.

    void name() {}
    void full_name() { counter++; }
};

void to_string(UserInterface* user)
{
    user->name();
    user->full_name();

Epilogue

We’ve added two new modes, regular functions and functors, providing a comparison of callback interfaces versus direct calls, with performance losses representing orders-of-magnitude differences. Functors perform close to functions, and sometimes even outperform them. The compilation aspect here was largely a knowledge blind spot; I suspected it was due to the access of variable addresses and the function being adjacent, which would benefit CPU processing.
