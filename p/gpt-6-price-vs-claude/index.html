GPT-6 降价以后，Claude 还值高价吗？

OpenAI把Sol和Luna推到更低价位，Anthropic也在降低Opus和Fable的实际任务成本

2026年09月23日 · 阅读时长: 10 分钟 · tianlong.xiang · v8.11.1
分类
  • AI 随笔杂谈
AI 写作

同一项编码任务，便宜模型做三遍、昂贵模型一次通过，哪一个更划算？答案不能只看模型名字，也不能只看每百万 token 的价格。重试用了多少上下文，人工检查花了多久，失败是否拖住后面的工作，都会进入实际成本。

9 月 22 日，GPT-6 Sol、Luna 与 Claude Opus 5.5 的价格变化，让这个问题更值得重算。OpenAI 把常用档位拉低，Anthropic 也在降低标价和缓存成本。“一家卖便宜，一家卖高质量”已经不足以描述两家的产品线。

先把同口径价格放在一起

下表比较 2026 年 9 月 23 日所讨论型号的标准文本 API 价，按每百万 token、美元计，未加入批量处理、长上下文、区域附加费和工具费用。GPT-5.6 Sol 使用当时已公布的促销价，不能把它当成永远不变的原价。

系列 型号 输入 输出 产品定位
GPT-5.6 Sol $4 $20 上一代旗舰，表内为促销价
GPT-5.6 Terra $2 $12 能力与成本平衡
GPT-5.6 Luna $0.20 $1.20 低成本、高吞吐
GPT-6 Astra $10 $50 复杂推理与高难度工作
GPT-6 Sol $2 $10 编码与多步 Agent 工作
GPT-6 Luna $0.10 $0.50 聚焦、重复、高调用量任务
Claude Fable 5.1 $10 $50 复杂、长时间、多阶段任务
Claude Opus 5.5 $4 $20 编码、知识工作与工具协作
Claude Sonnet 5 $2 $10 中档通用模型
Claude Haiku 4.5 $1 $5 较轻、较快的任务

GPT-6 Sol 相对表内 GPT-5.6 Sol，输入和输出均降一半。Luna 的输入从 $0.20 降到 $0.10，也是减半；输出从 $1.20 降到 $0.50，降幅约 58.3%，不能把两项都概括为恰好减半。GPT-6 Sol、GPT-6 Luna、GPT-5.6 Luna

在这次发布的 GPT-6 阵容中，Astra 占据顶层，Sol 落到接近上一代 Terra 的价位，Luna 继续向下探。名称相同，并不代表跨代承担同一个档位；比较 Sol 与 Sol 能看降价，比较 Sol 与旧 Terra 则更接近日常预算的迁移问题。产品发布时间可见官方更新记录。

Claude 也不只有 Fable 和 Opus。Sonnet、Haiku 仍构成更低档位，因此把整个品牌统称为高价，会遗漏它自己的价格梯度。

Luna 进入低价竞争，但两个样本不是整个市场

若只为比较方便，按 1 美元约 6.75 元人民币粗算，Luna 每百万 token 输入约 ¥0.68、输出约 ¥3.38。这是换算假设，不是对某笔账单结算汇率的承诺。

型号 输入 输出 比较范围
GPT-6 Luna 约 ¥0.68 约 ¥3.38 按上述汇率粗算的标准价
Qwen3.7 Plus ¥2 ¥8 阿里云北京区、输入不超过 256K 的标价
Qwen3.7 Flash ¥0.20 ¥0.80 北京区、输入不超过 32K 的标价

这里能得出的结论很具体：Luna 低于所列 Plus，仍高于所列 Flash。它说明 Luna 已进入可以与低成本国产模型一起比较的区间，却不足以证明“比很多国产模型便宜”。地区、上下文区间、缓存、批量调用和限时优惠都可能改变排序。阿里云价目说明

更不能把价格顺序变成质量顺序。格式抽取是否稳定、中文材料是否漏项、工具调用是否容易跑偏，需要用实际任务检验。低价只是让试验和大批量调用的门槛下降，并没有替用户完成选择。

一次完整任务怎样变成账单

先做一个只含输入输出的例子：假设同一任务使用 10 万输入 token、1 万输出 token，不含缓存和额外服务。

模型 按假设计算的单次费用
GPT-6 Luna $0.015
GPT-6 Sol / Claude Sonnet 5 $0.30
Claude Opus 5.5 $0.60
GPT-6 Astra / Claude Fable 5.1 $1.50

计算是输入量乘输入价，加输出量乘输出价；这里刻意固定 token 数，只看价格效应，不表示不同模型会用相同 token 完成同一任务。分词、推理、工具循环和生成长度都会改变实际用量。

这个例子也提醒人别过度美化高价模型的节省。如果便宜档已经能稳定通过验收，就没有理由为普通整理任务默认支付顶层价格。昂贵模型的优势需要体现为更少返工、更可靠的结果，或完成便宜档做不到的工作。

反过来，几十美分的差距也可能远小于一次人工排查的成本。一个模型省下了 token，却制造了难以察觉的错误，账单依然更贵。比较时应记录成功率、人工修订时间和最终交付成本，不能只比较一次调用。

缓存降价为什么会影响长任务

Agent 往往反复携带相似的项目背景和工具结果。首次输入和后续缓存读取的价格不同，因此基础单价不变，长任务的账单也可能下降。

Fable 5.1 的基础价仍为 $10/$50，缓存读取降到每百万 token $0.25，较此前下降 75%。Anthropic 根据自身工作负载估计，典型使用成本约降 25%，高 Agent 负载可降约 45%。Opus 5.5 则把基础价降到 $4/$20，缓存读取为 $0.20，公司估计典型任务成本可比 Opus 5 低约 40%。这些是厂商在特定负载上的估计，不是每个用户都能获得的折扣。Fable 5.1 说明、Opus 5.5 说明

如果提示词频繁变化、缓存命中少，收益就会不同；如果流程反复读取长上下文，缓存可能比一点基础单价差更重要。Anthropic 价目文档还说明，较新模型的分词方式可能让同样内容产生更多 token，平均变化取决于文本。跨厂商不能只把同一个 token 数当成相同工作量。Claude 计价说明

把模型放到有验收标准的工作里

官方定位可以帮助缩小试用范围，但不是实际质量的担保。

工作 可以先试的档位 应看什么结果
分类、抽取、固定格式整理 Luna、Flash 等低成本型号 漏项率、格式正确率、边界样本
日常编码和多工具维护 Sol、Sonnet、Opus 测试通过、改动范围、返工时间
陌生系统、复杂推理和高代价任务 Astra、Fable，也与 Opus 对照 是否真正降低失败与人工接管
长上下文反复执行 能力足够且缓存机制适配的型号 总 token、缓存命中与整项费用

把困难样本固定下来，会比每天看一张新榜单更有帮助。同一任务给不同模型相同材料和权限，用同一标准验收；记录失败类型，而不只给回答打一个印象分。若需要更强型号，最好能指出它解决了哪个具体缺口。

网上的早期反馈适合发现这些缺口，不能替代检验。发布日讨论中，有人关心降价后能多跑多少任务，也有人反映能力提升不明显或入口不稳定；Fable 讨论里则常把长任务效果与订阅额度消耗放在一起。这些只是所列论坛中的个人体验，没有随机样本和统一任务，不能写成多数用户的结论。

API 价与订阅体验也必须分开。一次 API 按 token 付费，订阅则受到套餐额度和产品规则影响。API 降价不保证订阅可用次数翻倍，也不保证每个入口同时开放。

两家公司都在争取同一笔预算：完成一项工作到底要花多少。OpenAI 这次把低价梯度推得更明显，Anthropic 则同时调整 Opus 标价和 Fable 的长任务成本。Claude 是否还值高价，没有适用于所有任务的答案。能明确说出它少犯了哪类错、少花了多少人工时间，这个溢价才有依据。
