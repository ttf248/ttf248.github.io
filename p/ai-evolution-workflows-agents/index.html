为什么说“超长工作流”是上个时代的互联网产品惯性

把时间拨回两年前，大模型刚起步的时候，工作流平台确实救了急。那时候模型推理能力弱、幻觉满天飞、连个 JSON 格式都输出不稳定，大厂又急着做出能落地的商业产品，于是把移动互联网时代最拿手的“可视化编排 + 精细化 SOP”搬了进来。

结果就变成了这样：模型不知道下一步干嘛？人来画一个 IF/ELSE 分支；模型提取网页总漏字段？人写一段 Python 代码节点兜底；工具调用报错？人再连一根重试线。画布上密密麻麻几十个节点，跑通的那一刻确实有成就感，但冷静下来算笔账就会发现：这哪是 AI 替人干活，分明是人在用自己的工程劳动，一点点给模型的智商打补丁。

我并不否认确定性流程的价值。财务报销找谁审批、数据库写入前做哪些合规校验，这些是真实世界里铁打的业务规则，模型再强也得老老实实遵守。但那些纯粹因为“模型以前太笨、不得不拆成二十步喂给它”的过渡性节点，随着基座模型自己学会了读文档、写代码、看报错、做自我修正，继续让用户手动维护它们，就从“赋能工具”变成了沉重的历史包袱。

大模型时代，用户想要的从来不是一张能把自己绕晕的流程图，而是一个能交付结果的伙伴：我把目标、材料、权限和验收标准交给你，你把全链路跑通，中间别动不动就卡死弹窗让我来替你擦屁股。

从 Workflow 到 Agent：把“纠错循环”还给系统

Anthropic 在其工程实践说明里给出过一个非常精准的切分：**工作流（Workflow）**是沿着人类预先画好的固定轨道协调模型和工具；**智能体（Agent）**则是由模型根据实时反馈，动态决定下一步调什么工具、走哪条路径。

这两者在实际体验上的分水岭，不在界面炫不炫酷，而在遇到意外和报错时，谁来接盘。

固定工作流只要遇到目标网页改了版、接口换了字段，整条流水线就立刻瘫痪，必须等人类工程师回来改节点。而真正意义上的 Agent 系统，应该把“试错—检查—修正”的闭环吞进系统内部：

flowchart TB
    accTitle: Agent 自主执行与自检循环
    accDescr: 用户提供目标与授权边界，系统规划并调用工具执行，自动检查结果并在未达标时调整重试，最终交付成果与核对证据。
    A["用户给出目标、材料与权限边界"] --> B["模型规划并调用工具"]
    B --> C{"检查执行结果是否达标"}
    C -->|未达标 / 遇到报错| D["读取错误信息并调整路径"]:::note
    D --> B
    C -->|达到验收标准| E["交付最终成果与可核对证据"]

只有当图里的自检与纠错循环真正由系统自己消化掉，用户不再充当整个 AI 系统的“人肉运行时”，全链路自动化才算真正开始。

现在的江湖：商业产品与开源生态都在抢哪一段？

顺着“把任务交给 AI”这条主线看今天的产品和开源社区，格局其实非常清晰——大家都在抢着接管不同场景下的执行闭环：

1. 商业产品：谁先把高频任务跑通

代表产品 核心战场与定位 真实体验门槛
Claude Code 扎根本地开发环境，直接读项目、改代码、跑测试、修 Bug 软件工程闭环极强，天然具备编译与测试作为客观验收尺
Codex CLI 在本地终端受约束地执行代码读取、重构与命令行任务 同样依托代码与终端生态，强调可控的工程交付
Cursor Agent 深度融合编辑器、代码检索、终端与浏览器预览 把人机协作与后台自主推进揉进了日常 IDE 动线里
Manus 浏览器能力 通过授权浏览器接管跨网页信息检索与操作任务 网页环境登录态与反爬复杂，仍强依赖用户授权与关键节点监督

2. 开源与源码可见项目：把 Agent 底座拆成积木

模型再强，状态怎么持久化、长任务断了怎么恢复、代码在哪跑才安全，依然需要扎实的工程底座。开源生态恰好在把这些脏活累活做成标准件：

工程沙箱与通用执行 OpenHands（编码 Agent 运行后端与画布）、DeerFlow（融合工具、记忆、技能与沙箱的深度研究/长任务框架） 字节自家也在开源探索脱离纯画布的长任务 Agent 路线
网页行动层 Browser Use（让大模型直接看懂并操作浏览器） 只是执行层抓手，不能单独替代完整的业务权限与风控体系

主流 AI 发展路线是什么，现在走到哪一步了？

如果跳出每天都在刷屏的模型跑分榜，把当下最主流的 AI 演进路线抽成骨架，其实是五条线在同时发力、互相咬合：

  1. 预训练底座继续抬高上限：数据清洗、合成数据与架构效率优化，仍在决定模型“见过多少世面、理解力有多深”。
  2. 强化学习后训练（Post-training RL）成为核心引擎：从 DeepSeek-R1 公开的技术路径就能看得很清楚——通过强化学习、冷启动与蒸馏，模型在代码、数学这类“结果可验证”的领域里，自主推理和纠错能力出现了断层式跃升。
  3. 推理时计算（Test-time Compute）换取深度思考：像 OpenAI 推理模型文档展示的那样，面对难题时让模型花更多算力和时间“多想几步”，不再指望单次前向传播蒙出正确答案。代价是时延和成本上升，且没有外部工具辅助时，光靠冥想也变不出缺失的事实。
  4. 原生多模态打通感知与操作：以 Google DeepMind Gemini 体系为代表，模型不再只是纯文本大脑，而是能直接看图、看视频、听音频、识别屏幕界面，为“像人一样操作电脑”铺路。
  5. Agent 执行系统接管长程记忆与环境：上下文窗口再大，把所有历史垃圾全塞进去也会让注意力稀释。通过文件系统、外部记忆、沙箱隔离和工具协议，让模型能跨越多轮交互持续推进大项目。

那我们离“完全不需要人干预”到底还有多远？

第三方评测机构 METR 维护的任务时间跨度基准（数据更新至 2026 年 9 月 8 日）提供了一个非常清醒的坐标：它用“人类专家完成该任务所需工时”来衡量 AI 在不同成功率（如 50%）下能独立搞定的任务长度。曲线确实在陡峭上扬，模型能连续自主推进的任务跨度比两年前长了几个数量级。

但 50% 的成功率，离日常生产环境里的“放手不管”还有不小距离。发个炫酷的 Demo 视频，只需要剪出成功的那一半；而真实工作里，剩下那一半——工具突然超时、网页换了按钮、跑了二十分钟忘了最开始的约束条件——才是决定用户敢不敢把核心任务交出去的生死线。

扣子企业版的退场只是一个缩影。工作流不会彻底灭绝，它会在需要严格审计、绝对确定性的企业业务底座里继续存在。但在面向个人和复杂知识工作的舞台上，逼着用户先当产品经理画流程图、再当运维修节点的时代，正在迅速翻篇。

真正属于大模型时代的好产品，应该把调度、重试、查资料和自检的复杂性全部吞进自己肚子里，只在真正缺信息、有冲突、或越过授权边界时才敲门问人一句。其余时候，请安静地把活干完，把结果和证据放在桌上。
