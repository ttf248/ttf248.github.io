让博客里的数据和流程动起来

一份可以复制的排版、图表和交互组件演示模板

AI 写作

有些内容，读者需要的是比较两个数字；有些内容，需要顺着一个分支走下去；还有些内容，只有亲手改一下参数，才容易看清结果为什么变了。这篇文章把这些表达放在一起，既展示效果，也留下能复制到下一篇文章里的写法。

先把最需要知道的事摆出来

这次接入的起点是一份 ChatGPT 分享对话。其中的并排卡片、曲线和滑块，适合把“文字里描述的关系”变成读者能直接观察的东西。博客里的实现使用 Hugo 组件；分享页中的 box、grid 和 slider 等语法需要转换，不能直接粘贴使用。

本页数字都是教学假设

下面的耗时、价格和任务位置都是为了演示排版与交互而设定的，不是性能实测、市场报价或真实任务记录。复制模板时，要同时替换数据、单位、期间和来源。

普通强调仍然有用。粗体适合让读者回看判断，斜体适合标注分析口径，行内代码用来区分参数和正文。不要因为有了卡片，就把每段话都塞进盒子里。

当一句话已经足够说明关系时，就让它保持一句话。

提示块的写法：

{{< callout kind="warning" title="口径提醒" >}}
这里写会影响结论的限制条件。
{{< /callout >}}

kind 可以是 note、tip 或 warning。标题要说清提示的内容，让含义不只依赖颜色。

比较方案时先统一字段

假设同一项工作有两种付费办法：方案甲每次 8 元；方案乙先付 200 元，此后每次 3 元。这里先用卡片交代规则，后面再让数量动起来。

方案甲：按次付费

固定成本 0 元，单价 8 元。 少量使用时起步成本低，使用次数增加后总成本增长较快。

方案乙：固定加按次

固定成本 200 元，单价 3 元。 需要先承担固定支出，使用次数足够多时才体现低单价的优势。

默认处理数量
20 次
用于下面比较器的初始情景
两方案成本相等
40 次
由 8q = 200 + 3q 算得

这里的 40 次由固定假设算出，不是普遍适用的决策门槛。没有写进模型的服务质量、税费和折扣，都不能从这个数字推出来。

{{< cards >}}
{{< card title="方案甲" >}}同一组比较字段。{{< /card >}}
{{< card title="方案乙" >}}同一组比较字段。{{< /card >}}
{{< /cards >}}

{{< metric label="处理数量" value="20" unit="次" note="教学假设" >}}

卡片适合少量概括，多字段查找仍用表格：

数量 方案甲总成本 方案乙总成本 在本模型中较低的一项
20 次 160 元 260 元 方案甲
40 次 320 元 320 元 相同
100 次 800 元 500 元 方案乙

数据图旁边也能查到原始值

下图演示类别比较：假设处理同一份材料，三种办法分别花费 40、16、10 分钟。柱子的长度帮助读者快速看差距，精确数值保留在图上和下方数据表里。

折线图则用于按顺序观察变化。这里是同一示例任务的四轮假设耗时，横轴按轮次等距排列，不表示真实日历时间。

图形、完整数据表和来源文字来自同一份 JSON。手机上可以在图内横向滑动查看；即使关闭 JavaScript，这两张图仍然存在。

把下面的文件保存为文章目录里的 duration.json：

{
  "title": "相同任务量的假设耗时",
  "unit": "分钟",
  "source": "教学构造数据；任务量相同，未做性能测试",
  "rows": [
    {"label": "手工处理", "value": 40},
    {"label": "脚本辅助", "value": 16},
    {"label": "模板复用", "value": 10}
  ]
}

正文只需要：

{{< data-chart src="duration.json" type="bar" >}}

连续轮次用 type="line"。图表支持负值和全零值；一张图放 2～24 项，更多数据应先汇总。折线中的点是等距类别，不适合冒充不等间隔的精确时间轴。

有分支的关系交给流程图

选表达方式，本身就可以画成一张流程图。先问读者要完成什么任务，再看是否需要改变参数，而不是看到一个数字就加一张图。

flowchart TD
    accTitle: 按读者任务选择表达方式
    accDescr: 连续论述用正文，数量比较用表格或数据图，步骤与分支用流程图，改变假设用交互组件。
    A[读者需要理解什么] --> B{主要任务}
    B -->|连续论述| C[自然段与必要强调]
    B -->|比较数量| D[表格或数据图]
    B -->|追踪步骤与分支| E[流程图]
    B -->|改变假设看结果| F[交互组件]
    D --> G[保留单位与来源]
    F --> H[保留默认结果与边界]

图上的按钮可以放大、缩小和复位；按住画布可以移动。用键盘时，聚焦画布后按方向键移动，按 +、- 缩放，按 0 复位。手机上在画布内拖图，在画布外继续滚动文章。

流程复杂到涉及多个参与者时，可以改用时序图。下面表示一篇交互文章从撰写到阅读的关系：

sequenceDiagram
    accTitle: 作者、博客与读者的交互顺序
    participant A as 作者
    participant B as 博客
    participant C as 读者
    A->>B: 写下数据、假设与默认结论
    B->>C: 展示正文与静态结果
    C->>B: 调整参数
    B-->>C: 更新数字和图形

两张图表达的内容在相邻文字中也能读到。图形未能加载时会保留源码；读者不必先理解源码，才能继续读文章。

复用时，在文章头信息中加入 mermaid: true，再放入带 mermaid 标识的代码围栏即可。图中放短标签，细节放回正文；这里的拖动改变查看位置，不会改写图的节点关系。

拖一下数量看看成本如何变化

回到前面的付费例子。两条线分别对应：

$$ C_A(q)=8q,\qquad C_B(q)=200+3q $$

其中 \(q\) 是处理数量，\(C_A\)、\(C_B\) 分别对应方案甲和方案乙，成本单位为元。拖动下面的滑块，观察数字、差额和曲线标记一起变化。也可以聚焦滑块，用方向键调整，用 Home、End 跳到端点。

同一数量下比较两种成本

来源与口径：教学假设；不含税费、服务差异和阶梯折扣；总成本 = 固定成本 + 单价 × 数量。单位：元。

20

默认数量 20：按次付费 160 元；固定加按次 260 元；

固定参数与端点成本（元）
方案固定成本单价数量 0数量 100
按次付费080800
固定加按次2003200500

在 20 次时，方案甲少花 100 元；到 40 次时两者相等；再增加数量，方案乙的低单价开始抵消固定支出。这里值得交互的是“数量变化如何改变比较结果”，不是让一个已经确定的数字动起来。

组件的调用只有一行：

{{< cost-compare src="costs.json" >}}

同目录的 costs.json：

{
  "title": "同一数量下比较两种成本",
  "unit": "元",
  "source": "教学假设；不含税费、服务差异和阶梯折扣",
  "quantity": {"label": "处理数量", "min": 0, "max": 100, "step": 1, "value": 20},
  "plans": [
    {"name": "按次付费", "fixed": 0, "rate": 8},
    {"name": "固定加按次", "fixed": 200, "rate": 3}
  ]
}

这个组件只计算固定成本加按次成本。它不会自动理解阶梯计费、复利或期权收益；换模型时，应另写一个专用实验，不能只改名字继续套用。

把专用实验放在一小块网页里

有时需要的交互不只是一个滑块。例如，下方把一项虚构任务放进“紧迫度—影响程度”平面。拖动圆点，位置与坐标一起变化；两个滑块提供同等操作，便于键盘使用。

拖动一个任务观察它的位置

初始位置是紧迫度 30、影响程度 70，落在“低紧迫、高影响”区域。坐标只是主观描述，没有自动算出真实优先级；实验用来观察两个维度怎样共同确定位置，不替读者安排任务。

打开交互实验

实验的 HTML、样式和脚本保存在本文目录的 priority-lab.html 中，可以整份复制后改写。点击“打开交互实验”展开；桌面上也可以拖动网页框右下角改变高度。嵌入写法如下：

{{< interactive src="priority-lab.html" title="任务位置实验" height="660" >}}
先用文字写出默认情景和实验边界。
{{< /interactive >}}

这块网页在独立沙箱中运行，不会改变博客的导航、正文或字号。它有自己的系统深浅色适配，不跟随博客手动选择的配色。实验打不开时，上面的默认解释仍然成立。

补充说明可以折叠但结论不要藏

这份模板如何保留阅读退路

静态数据图直接写在生成的 HTML 中；成本比较器保留默认结果、公式和端点表；流程图保留源码与相邻解释；网页实验保留正文摘要。折叠区域用于补充口径，不承担主结论。

打印时隐藏交互按钮和实验 iframe，保留正文、静态数据图与已绘制的流程图。若流程图尚未加载，仍可阅读文字说明与源码。

复制折叠块时，用 details 的 title 写清展开后能看到什么：

{{< details title="查看复算过程" >}}
这里写详细推导和补充边界。
{{< /details >}}

简短的来源补充也可以使用脚注1。文章目录仍由普通二级、三级标题生成，不需要把卡片标题再塞进目录。

这份模板刻意把多种表达集中在一页。写下一篇文章时，直接取能帮助读者完成当前任务的那一两种；一次有用的参数变化，比一页不停闪动的数字更有价值。
